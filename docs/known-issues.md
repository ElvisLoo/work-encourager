# 已知问题与设计取舍

## K-001 跨零点夜班在凌晨会「金额归零」🔴 未修

**现象**：班次设为 22:00 → 次日 06:00 时，凌晨 02:30 打开应用，`今日已到账` 显示 ¥0，状态显示「未开工」，进度回到 0。

**原因**：`earn.js` 的 `compute()` 以 `startOfDay(now)` 为基准构造当日计薪段。凌晨 02:30 时「今天」已经翻到新的一天，而新一天的班次从 22:00 才开始，因此落在 `before` 阶段。

**影响**：只在夜班用户身上出现；日班用户不受影响。

**当前处置**：v1.1.0 先锁定现状（`test/earn.edge.test.js` 有对应用例并注明原因），避免后续改动时无意引入回归。

**修复思路**：`compute()` 应同时尝试「以昨天为基准、班次跨越到今天」的候选段，取 `nowMs` 真正落在其中的那个。需要同步调整 `earn.edge.test.js` 中标记「锁定现状」的用例。

## K-002 负月薪时本月累计为负 🟡 未修

**现象**：`monthToDate()` 没有像 `rates()` 那样对月薪做 `Math.max(0, …)`，月薪填 -5000 时 `dayPay` 与 `total` 都是负数。

**影响**：极小。界面上月薪输入框 `min="0"`，正常操作填不进负数；只有手工导入 JSON 配置才会触发。

**修复思路**：在 `monthToDate()` 里同样夹取一次。属于一行改动，可直接并到下一个版本。

## K-003 工作日传入 0 曾被静默回落为 21 ✅ v1.1.0 已修

`Number(0) || 21` 使 0 被当成「缺省」而非「非法」。现统一走 `normWorkdays()`：显式 0 / 负数 → 1，缺省或非数字 → 21，上限 31。

---

## K-004 跨零点班次的午休完全没被扣除 ✅ v1.1.0 已修

班次 22:00 → 06:00、午休 02:00 → 03:00 时，原实现把 02:00 当作「当天 02:00」，与 22:00 起的区间没有交集，于是 1 小时午休被静默吞掉，计薪 480 分钟（应为 420）。

现按「休息开始时间早于上班时间即视为次日」处理，跨零点时整体 +1440 分钟后再求交集。

---

## K-005 `npm test` 在 Windows + Node 24 下无法运行 ✅ v1.1.0 已修

`node --test test/` 在 Node 24 被当作模块路径解析，报 `MODULE_NOT_FOUND`。改为 `node --test test/*.test.js`。

---

## K-006 v1.0.0 安装包没有卸载程序 ✅ v1.1.0 已修

v1.0.0 的 `npm run dist` 只带了 `--win` 未显式指定 `nsis`，产出的 `WorkEncourager-Setup-1.0.0.exe` 实为 electron-builder 的「解压工具」，不含 NSIS 安装器，因此：

- 没有 `Uninstall 牛马鼓励器.exe`
- 控制面板「应用和功能」里没有卸载项
- 只能手工删除 `%LOCALAPPDATA%\Programs\work-encourager`

v1.1.0 起 `npm run dist` 固定为 `--win nsis portable --x64`，CI 同步。
